**3. Division of Labor**

This is the operating model. Every build task maps to one of these two
lanes.

**3.1 Claude Does**

-   Write and iterate all code: HTML, CSS, JS, React/JSX, Python

-   Generate all copy: blog posts, email sequences, route descriptions,
    audio scripts

-   Design architecture: database schemas, system prompts, API flows,
    email logic

-   Review Antigravity output before building further on it

-   Create documents: PDFs, DOCX, structured markdown

-   Build generators and tools (blog generator, image prompt builder,
    etc.)

-   Prompt engineering: write the exact prompts for Imagen, Veo,
    ElevenLabs

-   Quality control: compare what Antigravity built vs. what was
    specified

**3.2 Antigravity Does**

-   Execute API calls requiring live keys: Imagen 3, Veo 2, ElevenLabs,
    Stripe, Supabase

-   Run and test code against real services locally

-   File system operations on C:\OpenRide.bike\

-   Local server (localhost:8000) --- running and hot-reloading

-   Push to GitHub / deploy to Netlify

-   Database operations: Supabase migrations, schema deploys, data
    seeding

-   Stripe checkout integration: product creation, webhook setup

-   Mapbox: tile requests, map rendering in browser

**3.3 The Handoff Protocol**

This is the workflow for every new feature:

1.  Claude designs and writes the code/prompt/architecture

2.  You paste it into Antigravity (or share the file)

3.  Antigravity runs it, creates/modifies files

4.  You share output (screenshot or paste code) back to Claude

5.  Claude reviews, catches problems, specifies next iteration

6.  Repeat until done --- then move to next feature

+-----------------------------------------------------------------------+
| **RULE: NEVER BUILD FURTHER ON UNREVIEWED OUTPUT**                    |
|                                                                       |
| If Antigravity generates a file and you haven't shown it to Claude    |
| first,                                                                |
|                                                                       |
| do not build the next layer on top of it. Paste or screenshot it here |
| first.                                                                |
|                                                                       |
| This prevents compounding errors and wasted build time.               |

**5. Media Generator Spec (Antigravity Build Target)**

This is the exact spec to give Antigravity for the Imagen 3 / Veo 2
media generator.

**5.1 What to Build**

-   Filename: openride-media-generator.html in C:\OpenRide.bike\

-   Standalone HTML tool --- no framework, no build step

-   Two modes toggled at top: Image (Imagen 3) and Video (Veo 2)

-   Google Generative AI API --- use same key as other project

**5.2 Shot Categories & Prompts**

Each category has pre-built prompt templates. Claude will provide full
prompt text in session.

-   On the Bike --- POV road ahead, hands on bars, rider from behind,
    group riding, descent, climb

-   Points of Interest --- Natchez Trace mileposts, historic ruins,
    scenic overlooks, bridges, churches

-   Rest Stops & Food --- diner counter, gas station stop, bike leaned
    outside cafe, picnic lunch

-   Lodging & End of Day --- B&B porch with bikes, bike in room,
    breakfast table, sunset arrival

-   Landscape & Atmosphere --- misty morning, Spanish moss, fall
    foliage, storm coming, golden hour

-   People & Moments --- couple at viewpoint, solo rider at rest,
    talking to local, group laughing

**5.3 Controls Required**

-   Route selector: Natchez Trace / GAP / Katy Trail / Oregon Coast /
    Blue Ridge / Generic

-   Season: Spring / Summer / Fall / Winter

-   Camera style: iPhone snapshot / GoPro POV / Mirrorless / Film grain

-   Generate button → displays image grid with download buttons

-   Each image labeled with suggested filename (e.g.
    natchez-trace-morning-pov.jpg)

**5.4 Critical Prompt Direction**

+-----------------------------------------------------------------------+
| **EVERY IMAGEN/VEO PROMPT MUST INCLUDE THESE ELEMENTS**               |
|                                                                       |
| • Real touring cyclist --- NOT racing kit. Practical cycling clothes, |
| loaded panniers visible                                               |
|                                                                       |
| • Candid/authentic --- NOT staged, NOT stock photo, NOT AI aesthetic  |
|                                                                       |
| • Specific location details baked in per route (Spanish moss =        |
| Natchez, limestone bluffs = Katy, etc.)                               |
|                                                                       |
| • Camera style modifier on every prompt (iPhone snapshot / GoPro wide |
| / mirrorless bokeh / film grain)                                      |
|                                                                       |
| • Time of day specified (morning mist, midday sun, golden hour, dusk  |
| arrival)                                                              |
|                                                                       |
| • Human scale --- bike and rider in frame at correct proportion to    |
| landscape                                                             |
+-----------------------------------------------------------------------+

**5.5 Image Prompt Rules (Apply to Every Route, Every Batch)**

+-----------------------------------------------------------------------+
| **LOCATION VERIFICATION — REQUIRED BEFORE WRITING ANY PROMPT**        |
|                                                                       |
| Every named location in a prompt must be verified as real, currently  |
| accessible, and accurately described from actual photos or listings.  |
|                                                                       |
| • POIs: mounds, ruins, historic sites, overlooks — confirm open,      |
|   confirm current access (e.g. Windsor Ruins is fenced since 2023)    |
|                                                                       |
| • Lodging: confirm operating, describe architecture from real photos  |
|   only — never from imagination                                       |
|                                                                       |
| • Diners/stores: real named establishments only. If unverifiable,     |
|   use a fully generic description with NO name and NO signage         |
|                                                                       |
| • Campgrounds: confirm open, describe accurately                      |
|                                                                       |
| Generic/unnamed scenes (unnamed rest stops, unnamed roads, unnamed    |
| overlooks) are fine — just no invented names or specific signage.     |
+-----------------------------------------------------------------------+

+-----------------------------------------------------------------------+
| **NO INTERIOR SHOTS WITHOUT A REFERENCE IMAGE — NO EXCEPTIONS**       |
|                                                                       |
| If a prompt depicts the inside of any building — diner, gas station,  |
| B&B bedroom, restaurant, shop, any interior — it requires:            |
|                                                                       |
| 1. A real verified location (named, confirmed operating)              |
| 2. A reference photo of the actual interior                           |
|                                                                       |
| If either is missing, the prompt is CUT. Do not write a generic       |
| interior. Do not approximate. Cut the shot and replace it with an     |
| exterior or outdoor scene at a real verifiable location.              |
|                                                                       |
| Reason: people see these images and want to go there. A generic       |
| interior is a dead end — there is no "there" for them to find.        |
+-----------------------------------------------------------------------+

+-----------------------------------------------------------------------+
| **RIDING SHOTS — FACES RULE**                                         |
|                                                                       |
| Imagen 3 ignores "from behind" camera direction. Fix: describe the    |
| scene so faces are physically impossible to show.                     |
|                                                                       |
| • "Camera at road level behind the riders" — not "shot from behind"  |
| • "Backs, helmets, and road ahead visible"                            |
| • "No faces visible. No one looking back." — add explicitly           |
| • Never use direction language alone. Make it structural.             |
+-----------------------------------------------------------------------+

+-----------------------------------------------------------------------+
| PREFERRED IMAGE WORKFLOW — REAL PHOTO + GEMINI EDIT                   |
|                                                                       |
| For all POI shots, lodging exteriors, and named locations:            |
|                                                                       |
| STEP 1 — fetch_reference_images.py                                    |
| Run for the route. Pulls real photos from Wikimedia Commons and NPS   |
| automatically into routes/[Route Name]/Reference Images/              |
|                                                                       |
| STEP 2 — Gemini image editing (gemini.google.com)                     |
| Drop the real reference photo into Gemini. Use this prompt:           |
|                                                                       |
| "Add two touring cyclists with loaded panniers in the foreground.     |
|  Candid, not posed. Helmets on. Cycling jerseys. They are looking     |
|  at the location, not the camera. Keep the background completely      |
|  unchanged. Photorealistic."                                          |
|                                                                       |
| Adjust for solo rider, couple, or group as needed.                    |
|                                                                       |
| STEP 3 — Save output to images/{route}/                               |
| Use the standard filename from prompts.json for that shot.            |
|                                                                       |
| WHY THIS BEATS IMAGEN ALONE:                                          |
| Real signage, real architecture, real light. Imagen generating from   |
| scratch gets the location "close but off." Gemini editing a real      |
| photo produces the exact location every time.                         |
|                                                                       |
| USE generate_images.py (Imagen 3) FOR:                                |
| Riding shots, rest stops, camping, generic road scenes —              |
| anything where exact location details don't matter.                   |
|                                                                       |
| USE GEMINI EDIT FOR:                                                   |
| Named POIs, lodging exteriors, historic sites, landmarks —            |
| anything where real location details matter.                          |
+-----------------------------------------------------------------------+

## PDF Preview Standard

All route guide pages that show PDF previews (sample guide, cue sheet)
MUST use the modal-blur-overlay pattern. Never show the full PDF.
Rules:
- iframe shows the real PDF file
- .modal-blur-overlay covers the bottom 65% with a fade
- CTA button links to the correct Stripe checkout for that segment
- "Purchase to unlock" messaging always present
- CSS classes: modal-blur-overlay, modal-blur-cta, modal-blur-btn
- These classes must be in the <style> block of every route page

Copy the pattern from natchez-trace-lower.html. Do not deviate.
